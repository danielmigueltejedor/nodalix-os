# Nodalix OS 0.5.1

A maintenance release on top of 0.5.0: fixes for installs that were left
half-updated, a more consistent Appearance panel and login screen, a Store
that shows the Nodalix icons, and hardening of the privileged helpers.

- The updater now detects an installation whose version matches but that is
  missing required Nodalix packages, and repairs it instead of reporting
  "up to date". A release key that pacman does not own no longer blocks the
  updater's own upgrade.
- Animated backgrounds in Appearance use the same grid as the static ones, with
  the same thumbnail size, rounding, selection marker and single-click
  selection. Before, every wallpaper took a full row. Thumbnails of videos you
  import now have the same shape as the packaged ones.
- Switching from an animated wallpaper to a static one also updates the login
  screen. The new picture is published once, remembered, and not requested again
  (so no repeated authentication prompt for the same image), and PNG or WebP
  pictures are converted automatically. The lock screen no longer keeps the
  video's still frame.
- Nodalix Store is now called "Store" and follows the system language, like
  the stock apps of other systems: "Tienda" in Spanish, "Botiga" in Catalan,
  "Boutique" in French, "Loja" in Portuguese and so on. Its update
  notifications use the same name and icon.
- Nodalix Store has its own icon in the Nodalix icon theme instead of the Bazaar
  one, and its catalog shows the Nodalix application icons, including apps that
  are not installed yet and entries loaded from the cache. Icon lookups are
  shared, which makes scrolling the catalog lighter.
- `nodalix-store` replaces `bazaar` cleanly during an upgrade instead of
  stopping on conflicting files.
- Now Playing Card shows on secondary monitors too, and the centre of every
  panel keeps all of its indicators.
- Nodalix Icons (Colloid application icons with Adwaita system symbols) is the
  default icon theme; the cursor remains selected separately.
- The login background helper decodes the picture as the unprivileged `nobody`
  user with memory, time and file limits, and the root process only validates
  and publishes the result.
- NXPM verifies AppImages before import and update, streams large downloads to
  disk, writes its catalog atomically, and refuses system upgrades or package
  removals while another package manager holds its lock. A stable release that
  already has assets can no longer be overwritten by a later upload.
